구글 RTB bid request가 동일 지면 기준 5,000건 이상 수신되면 시스템이 부모 지면을 자동 생성한다.
기존 지면과 ①앱네임(또는 최상위 도메인) · ②광고노출 위치 · ③리워드 여부
3가지 조합이 일치하면 자식 지면으로 연결되고, 일치 조합이 없으면 심사 대기 상태로 부모 지면이 등록되어 운영자 승인 절차를 거친다. 부모 지면 생성 시 입찰 전문의 리워드 여부(rwdd)를 확인해 N / Y 부모 지면을 분리 생성한다. (N : 기존과 동일 / Y : 지면명·태그 ID 끝에 _reward)
자식 지면은 자신의 리워드 여부와 같은 리워드 여부의 부모 지면 하위로만 연결된다. (N → N 부모 / Y → Y 부모)261001_수정

STEP 01 · 자동 생성

bid request 5,000건+ 감지

동일 지면 조건으로 입찰 요청이 임계치를 넘으면 부모 지면이 자동 채번·생성된다.
최초 수신일이 생성일 기준이 된다.리워드 여부(rwdd)에 따라 N 부모 / Y 부모(_reward)로 분리 생성된다.261001_수정

STEP 02 · 심사

운영자 승인 / 반려

조합 일치가 없는 신규 부모 지면은 '심사 대기'로 진입한다. 승인 시 카테고리 지정 후 시스템심사로 진행된다. 반려 시 지면 사용 불가로 종료되며, 재심사는 없다.261001_수정

STEP 03 · 라이브

자식 지면 연결 후 송출

승인·시스템심사 통과 후 연결된 자식 지면이 있으면 실제 라이브가 가능하다.
자식 지면이 없으면 송출 대상이 없는 상태로 남는다.자식 지면은 리워드 여부가 같은 부모 지면 하위로만 연결된다.261001_수정

3지면명261001_수정매체명 + rwdd 공통
부모 지면 자동 생성 규칙([부모지면등록] [10] 참고) : 리워드 여부 N → RTB_WEB(MOB/APP)_매체명 (기존과 동일) / 리워드 여부 Y → RTB_WEB(MOB/APP)_매체명_reward.
4매체 상세site 객체 / app 객체 공통입찰 전문에 site 객체 존재 → WEB, app 객체 존재 → APP 표시.
5노출 형태imp.banner / native.request / instl 공통imp 노출 단위 기준 표시 : banner 객체 → 배너, native.request → 네이티브, instl=1 또는 banner.pos=7 → 전면.
전면 광고는 CTR이 높아 일반 배너와 분리 운영 대상. 하나의 요청에 노출(구좌)이 여러 개인 경우 imp.id로 구분.

부모 지면 생성 시 이 값으로 N 부모 / Y 부모를 분리하며, 자식 지면은 같은 값의 부모 지면 하위로만 연결된다.
